### Введение

DNS-туннелирование — метод скрытой передачи данных через инкапсуляцию полезной нагрузки в DNS-запросы и ответы. Согласно отчёту IDC [3], 90% организаций подвергались DNS-атакам в 2023 году, при этом DNS-туннелирование остаётся одним из основных векторов эксфильтрации данных. Данный канал активно используется вредоносным ПО для организации управляющих соединений (C2), поскольку DNS-трафик редко блокируется межсетевыми экранами [1].

В контейнерных средах Kubernetes проблема детекции усложняется: необходимо идентифицировать не только процесс-источник, но и конкретный pod и namespace. Технология eBPF (extended Berkeley Packet Filter) позволяет выполнять трассировку сетевых пакетов на уровне ядра Linux с минимальными накладными расходами [2], что делает её перспективной для решения данной задачи.

**Цель работы** — разработка прототипа системы обнаружения DNS-туннелирования на основе eBPF с поддержкой идентификации контейнеров в Kubernetes.

---

### Архитектура системы

Разработанная система состоит из двух компонентов:

1. **eBPF-модуль** — перехватывает DNS-трафик через kprobe на функциях `udp_sendmsg`, `udp_recvmsg`, `tcp_sendmsg`, `tcp_recvmsg`. Извлекаются: PID процесса, идентификатор cgroup, DNS-payload (до 256 байт), временная метка ядра, IP-адреса.

2. **Python-агент** — получает события через Perf Buffer, парсит DNS-пакеты, резолвит cgroup_id в имя пода через cgroup-путь (`/proc/<pid>/cgroup`) и Kubernetes API, применяет эвристические детекторы, экспортирует метрики в Prometheus.

Система развёртывается как DaemonSet — по одному экземпляру на каждом узле кластера.

---

### Методы детекции

Реализованы три эвристических детектора:

**1. Детектор C2-beacon.** Анализирует регулярность DNS-запросов к домену от одного процесса. Вычисляется коэффициент вариации (CV) временных интервалов; значение CV < 0.15 при >= 5 запросах с интервалом > 5 сек сигнализирует о периодическом beacon-поведении. Также детектируются TXT-запросы к нетипичным доменам.

**2. Детектор эксфильтрации.** Применяет энтропию Шеннона для выявления закодированных данных в субдоменах. Пороговые значения: энтропия > 4.0 бит/символ, длина домена > 60 символов, доля цифр > 30%. Дополнительно распознаются Base64 и hex паттерны в субдоменах [1].

**3. Детектор IP-over-DNS.** Идентифицирует туннели типа iodine: NULL-записи (QTYPE=10), высокая частота запросов (> 50/сек в окне 10 сек), аномальное количество ответов (> 5).

---

### Особенности реализации

- **Kubernetes-интеграция:** резолвинг cgroup_id → pod/namespace через парсинг `/proc/<pid>/cgroup` и запрос к Kubernetes API
- **Prometheus-метрики:** `dns_queries_total`, `dns_suspicious_events`, `dns_domains_unique` с лейблами `client_pod`, `namespace`, `threat_type`
- **Helm Chart:** готовый пакет для развёртывания с ServiceMonitor для Prometheus Operator
- **Grafana Dashboard:** визуализация метрик, топ подозрительных доменов и подов

---

### Заключение

Разработан прототип системы обнаружения DNS-туннелирования для Kubernetes на основе eBPF. Ключевые результаты:

- Реализован перехват UDP/TCP DNS-трафика на уровне ядра
- Обеспечена атрибуция трафика к конкретному pod/namespace
- Реализованы три эвристических детектора (C2, exfiltration, IP-over-DNS)
- Система интегрирована с экосистемой мониторинга Kubernetes

Направления дальнейшей работы: оптимизация извлечения DNS-payload в eBPF для различных версий ядра, добавление ML-классификатора для DGA-доменов, расширение набора детекторов.
