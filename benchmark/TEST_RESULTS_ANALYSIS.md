### Известные ограничения

#### 1. TCP через `dig +tcp`

**Проблема**: Данные не парсятся для `dig +tcp`

**Причина**: 
- `dig` отправляет TCP DNS данные через несколько вызовов `sendmsg()`
- Length prefix (2 байта) может быть отправлен отдельно от DNS данных
- Данные могут быть разбиты на несколько буферов в `iov_iter`
- К моменту `kretprobe` указатель на данные может быть невалидным

**Техническое объяснение**:
- `tcp_sendmsg()` может вызываться несколько раз для одного DNS запроса
- Первый вызов может содержать только length prefix
- Второй вызов содержит DNS данные
- eBPF перехватывает не тот вызов, где находятся DNS данные

**Решение**:
- ✅ **Работает**: Прямой socket (Python) - данные отправляются одним вызовом
- ❌ **Не работает**: `dig +tcp` - множественные вызовы
- 🔄 **В разработке**: Попытка чтения из `msg->msg_iter` в `kretprobe`

#### 2. TCP RESPONSE парсинг

**Проблема**: Многие TCP RESPONSE показывают `<unparseable>`

**Причина**:
- TCP RESPONSE может быть большим (до 64KB)
- Данные могут быть разбиты на несколько пакетов
- Length prefix может быть в отдельном пакете
- Некоторые ответы содержат несколько DNS записей

**Статус**: 
- Частично работает (40% успешных)
- Некоторые ответы парсятся корректно
- Проблема в основном с большими ответами
